# sync-project-context

하네스 작업 완료 후 CLAUDE.md의 프로젝트 설명 섹션을 현재 코드 상태와 동기화한다.

## 핵심 원리

- **다음 세션의 에이전트가 코드를 한 줄도 읽지 않고도 "이 시스템이 뭘 하고, 어떤 흐름으로 동작하며, 왜 그렇게 설계됐는지" 이해할 수 있어야 한다.**
- 단순 나열이 아니라 설계 의도가 드러나는 서술이어야 한다.

## 갱신 대상

`CLAUDE.md` 내 `## Project Description` 섹션만 교체. 다른 섹션은 건드리지 않는다.

## 정보 수집

코드에서 직접 읽는다. 추측 금지. 스택별 grep 명령은 프로젝트 컨벤션에 맞춰 정한다.

## 출력 형식

```markdown
## Project Description

### 시스템 개요
(2~3문장)

### 구조도
\`\`\`mermaid
graph TD
...
\`\`\`
(다이어그램 아래에 "왜 이 구조인지" 한 문장)

### 주요 흐름
\`\`\`mermaid
sequenceDiagram
...
\`\`\`
(다이어그램 아래에 설계 의도 한 문장)

### 기능 목록
- 유저 관점 기능 단위로 작성

### 주요 인터페이스
| ... | ... |
```

## 작성 지침

- **구조도**: 모듈 의존 방향과 통신 방식이 드러나야 한다. 흐름의 뼈대만.
- **시퀀스**: 핵심 흐름 1~2개만. 나머지는 표로 충분.
- **설계 의도**: 매 다이어그램 아래에 "왜"를 한 문장. 없으면 다음 에이전트가 구조 변경 가부 판단 불가.
- **기능 목록**: "~할 수 있다" 형태.
